# MariaDB 4.0.0-beta Implementation Plan

> **For agentic workers:** Execute the independent configuration and schema-verifier tasks in parallel, then integrate and rehearse locally. No deployment/publishing authority is granted by this plan.

**Goal:** Make the current application run correctly on MariaDB 12.3.3 and preserve the v3.2.0 MySQL fallback.

**Architecture:** New database volume and logical restore; same application connections. Engine-aware schema verification preserves the existing contracts. Content-sync compatibility is deferred.

**Tech Stack:** Docker Compose, MariaDB 12.3.3, MySQL 5.7, Node mysql driver, Python/PyMySQL.

**Spec:** `docs/superpowers/specs/2026-09-07-mariadb-design.md`.

## Global constraints

- Keep version `4.0.0-beta`; preserve `v3.2.0` and all existing tags.
- Never reuse a MySQL data directory for MariaDB.
- Do not touch user-owned `docker-compose-prod.yaml` or existing local services.
- No content-sync compatibility implementation, server deployment, image publication, or push.
- No credentials, private database rows, or environment-file contents in logs.
- linux/amd64 must be available; live Builder is the primary acceptance path.
