# Release 3.2.0 and Start the 4.0 Development Cycle

> **For agentic workers:** Use inline execution for this release checklist. The maintainer has authorized the stable release and the next major development cycle; production deployment is excluded.

**Goal:** Preserve the current MySQL application as release 3.2.0 before MariaDB work begins in 4.0.0-beta.

**Architecture:** Promote the existing 3.1.0-beta change set to 3.2.0 without application or database changes. Create an annotated stable tag and GitHub release, then advance master to 4.0.0-beta in a separate commit. Git tags and images preserve software; a private database backup is separately required to preserve data.

**Tech Stack:** Git, GitHub CLI, Node.js, Docker Buildx.

**Spec:** Maintainer instructions in this conversation, 2026-09-07: cut 3.2 now, reserve MariaDB work for 4.0, do not deploy production. Content sync remains disabled and its compatibility work is deferred.
