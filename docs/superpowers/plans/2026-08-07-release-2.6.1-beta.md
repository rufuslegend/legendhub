# LegendHUB 2.6.1-beta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prepare a locally verified `2.6.1-beta` release that corrects the stale public changelog introduction and prevents that mismatch from recurring.

**Architecture:** Root `CHANGELOG.md` remains the public source of truth copied into the web image. The release verifier will continue comparing the newest release heading with package, lockfile, and badge metadata, and will additionally compare the changelog introduction with the oldest retained release heading.

**Tech Stack:** Node.js 22, `node:test`, npm lockfile v3, Markdown, Docker Compose v2 validation.

## Global Constraints

- Work only on local branch `release/2.6.1-beta` in its isolated worktree.
- The exact target version is `2.6.1-beta`.
- Preserve the released `2.6.0` changelog section.
- Never move, delete, or reuse immutable tags `v2.6.0-beta` or `v2.6.0`.
- Do not push, tag, publish images, or deploy without separate explicit authorization.
- Do not touch root `docker-compose-prod.yaml` or any secret-bearing file.

### Task 1: Protect changelog beginning-version metadata

**Files:**
- Modify: `scripts/test/verify-release-version.test.js`
- Modify: `scripts/verify-release-version.js`

**Interfaces:**
- Consumes: changelog headings in `## [version]` format and the sentence `documented here beginning with version <version>.`
- Produces: `verifyReleaseVersion(repoRoot) -> string`, returning the newest release version only when the introduction matches the oldest retained release.

- [ ] **Step 1: Extend the test fixture and add the failing regression test**

Change `createFixture()` so generated changelogs contain an introduction, may contain an older retained release, and may override the beginning version:

```js
const beginningVersion = overrides.beginningVersion || version;
const olderRelease = overrides.olderVersion ?
    `\n## [${overrides.olderVersion}] - 2026-08-05\n\n### Fixed\n\n- Earlier release.\n` : "";
const introduction = overrides.omitBeginning ? "" :
    `All notable user-facing changes are documented here beginning\nwith version ${beginningVersion}.\n\n`;

fs.writeFileSync(path.join(root, "CHANGELOG.md"),
    `# Changelog\n\n${introduction}${overrides.unreleased ? "## [Unreleased]\n\n- Pending change.\n\n" : ""}## [${version}] - 2026-08-07\n\n### Fixed\n\n- Safer startup.\n${olderRelease}`);
```

Add a test proving the current verifier wrongly accepts the production mismatch:

```js
test("rejects a beginning version that differs from the oldest release", (t) => {
    const root = createFixture({
        version: "2.6.1-beta",
        olderVersion: "2.6.0",
        beginningVersion: "2.6.0-beta"
    });
    t.after(() => fs.rmSync(root, {recursive: true, force: true}));
    assert.throws(() => verifyReleaseVersion(root),
        /CHANGELOG\.md.*beginning version.*2\.6\.0-beta.*oldest release.*2\.6\.0/i);
});
```

- [ ] **Step 3: Implement the generalized verifier check**

In `verifyReleaseVersion()`, replace the current newest-heading selection with release-only headings:

```js
const releaseHeadings = headings.filter((heading) => heading[1] !== "Unreleased");
const changelogMatch = releaseHeadings[0];
```

After validating the newest heading, parse and validate the introduction:

```js
const beginningMatch = changelog.match(
    /documented here beginning\s+with version ([0-9A-Za-z.+-]+)\./);
const beginningVersion = beginningMatch?.[1];
const oldestVersion = releaseHeadings.at(-1)?.[1];

if (!beginningVersion || !semanticVersion.test(beginningVersion))
    throw new Error("CHANGELOG.md does not contain a valid beginning version");
if (!oldestVersion || !semanticVersion.test(oldestVersion))
    throw new Error("CHANGELOG.md does not end with a valid semantic version heading");
if (beginningVersion !== oldestVersion) {
    throw new Error(
        `CHANGELOG.md beginning version ${beginningVersion} does not match oldest release ${oldestVersion}`);
}
```

- [ ] **Step 4: Add positive and missing-metadata coverage**
